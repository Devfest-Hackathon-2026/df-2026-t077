# 公開版のデバッグ記録（2026-11-10）

対象：`https://zurashitabi.web.app/` と修正版のローカル画面。作業ブランチは `feat/cd-frontend-finish`。
前回のフロント変更を保持し、`git merge --autostash origin/main` でmain `95d838a`を取り込み済み。Gemini説明の更新はmainから取り込んだもので、今回A/Bの業務コード・API契約・施設/経路データ・依存lock・個人.envは編集していない。commit/push・GitHub上のmainへの反映・再デプロイは行っていない。

## 原因と修正

| 確認したこと | 原因・対応 |
|---|---|
| 英語の比較画面に日本語の警告が表示される | UIのラベルだけ翻訳し、APIのwarningsをそのまま表示していた。既知の定型警告を日英で表示する共通部品へ統一。 |
| 理由・不利益・不確実性も日本語のまま | Proposalの説明とFactは生成時の言語で保存される。保存データを変更せず、既知の定型Factを表示言語へ切替。場所名・紹介文は確認済みのSpotの日英フィールドを使い、数値・符号・根拠IDは保つ。 |
| 任意のGemini文章は定型辞書にない | 勝手な翻訳を捏造しない。翻訳できる保存済みFactがあれば、そのFactによる要約であると明示し、元のAI文章は原文を開いて確認可能にした。未対応の不利益・注意文も省略せず原文への入口を表示。 |
| 英語のSpot詳細に日本語の出典メモが混在 | 日本語のタイトル・注記・提供元を「Source information (Japanese)」としてまとめ、1操作で原文を確認できる。確認日時・情報種別・確度・出典リンクは常時表示。 |
| 言語切替で意図せず別の案にならないか | UI切替だけでは生成/採用を呼ばない。時刻・距離・Tripの保存言語・Fact配列・採用IDが変わらないことを実APIで検査。新しい言語で生成する入口は本人の再確認を経る。 |
| 公開版を再読み込みすると日本語に戻る | 前回の修正版にあるUI言語保持が公開版へ未反映。今回も英語維持・同じ採用の復元を再確認した。 |
| 待ち時間不明なのに0分に見える | 前回の未算入表示修正が公開版へ未反映。修正版では未入力の行列待ち時間を「Not included」と表示し、実測0分とは区別。 |

主な追加部品：`i18n/serverText.ts`、`i18n/plannerTextPairs.ts`、`components/ui/ServerText.tsx`、`SourceSummary.tsx`、`features/why/PlanSummary.tsx`。既知文は全文一致・既知の定型形式だけを扱う。未知の文章や、現在の候補/紹介文と一致しない内容を推測で置換しない。将来backendの文言や形式が変わる場合はこの辞書も確認する。

## 公開版を実際に操作した結果

- 英語の手入力、候補12地点の取得、must/optional、回避希望を設定し、元案・時間案・場所案を生成できた。名古屋城mustを保ち、時間案は順序変更、場所案は大須商店街を万松寺へ交換した。
- 時間案を採用し、GETの保存画面がversion 2になることを確認。再提案後も採用ID/versionを維持し、再読み込み後にも同じ旅程を表示した。
- 英語UIのまま日本語の説明言語を指定して再提案すると、スクリーンショットと同じ混在を再現できた。
- 英語の自由文から、名古屋城must・歴史・徒歩8kmを読み取り、本人が選んだ項目だけフォームへ反映できた。未確認の内容でTripは作成しない。
- 説明の一部が定型fallbackになっても、比較と採用は継続できた。
- 公開版の地図Webキーは未設定と画面に表示される。実地図の描画成功は確認していない。

入力時刻の確認候補：`must return by 5 pm` は英語の未解決事項になった。フォームの終了時刻は空のまま維持され、本人入力で継続できる。B側で英語の時刻表現の取りこぼし候補として確認する。モデル生出力を保存しておらず、原因は断定しない。

日付自動入力の補足：IABの自動fill直後に「先に旅行日」の表示が残る状態を観測したが、ネイティブ操作で日付を確定すると公開版でもAI整理が有効になった。一般利用で恒常発生する不具合とは断定しない。修正版ではAI整理へ親フォームと同じ旅行日を渡し、言語切替・日付削除・再入力の回帰検査を追加した。
