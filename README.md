# ずらしたび / Zurashitabi

**行きたい気持ちは、そのままに。時間と場所をずらして、旅の選択肢を広げる。**

- **公開アプリ： [zurashitabi.web.app](https://zurashitabi.web.app/)**（日本語 / English）
- **チーム：ミジュマル** — DevFest GDGoC Japan 2026 Hackathon・観光カテゴリー・名古屋会場


## どんなアプリか

「名古屋城には必ず行きたい。でも、限られた時間の中で、ほかの場所も楽しみたい。」

ずらしたびは、**必ず行きたい場所を守りながら、時間をずらす案と場所をずらす案を比較できる、旅行前の半日〜1日プランナー**です。英語で情報を探す訪日個人旅行者を主な利用者とし、日本語で計画する国内旅行者にも対応します。

同じ場所・同じ時間への観光の集中を和らげる選択肢と、旅行者がまだ知らない地域の魅力に出会うきっかけを作ることを目指しています。現在は、名古屋城・栄・大須周辺の**実在12地点、徒歩移動、日本語・英語**を対象としています。

## 大事にしていること
- **必ず行きたい場所・固定時刻・帰りの時刻・歩行上限は守る。** 時刻や距離の計算はプログラムが行い、AIには任せません。
- **情報には出典がある。** 営業時間や紹介文は公式情報をもとにチームが確認しました。徒歩経路はGoogle Mapsの推定です。
- **AIの役割は2つだけ。** 希望の文章をフォームの下書きにすることと、確定した事実から案の要約を書くこと。検証に通らないAIの出力は使いません。
- **決めるのは本人。** アプリは選択肢と理由を出し、採用は本人が行います。

## 使い方・動作例

審査・体験には、セットアップ不要の[公開アプリ](https://zurashitabi.web.app/)をご利用ください。メールアドレスやパスワードの登録は不要です。

### 1. 行きたい希望を入力する

たとえば、次の条件で計画します。

| 項目 | 入力例 |
|---|---|
| 旅行日・時間 | 2026/11/12、09:00〜17:00（日付は必要に応じて変更） |
| 出発・帰着 | 栄駅から出発し、栄駅へ戻る |
| 歩行上限・訪問上限 | 8km、4か所 |
| 楽しみたい体験 | 歴史 |
| 必ず行きたい場所 | 名古屋城 |
| 代わりの場所でもよい訪問先 | 大須商店街 |
| 避けたい時間帯 | 名古屋城の09:00〜11:00。本人の希望として設定 |
| 待ち時間 | 未入力でも利用可能。不明として扱う |

ほかの訪問先が決まっていなければ「お任せします」も選べます。

日本語・英語の自由文から、AIに入力の下書きを作らせることもできます。

> I must visit Nagoya Castle. I like history and local food.

**読み取り結果は本人が確認・修正してから反映します。** 曖昧な時刻や未知の場所を、AIが勝手に確定することはありません。自由文を使わず、フォームだけでも計画できます。

### 2. 元案と、時間・場所をずらす案を比較する

| 案 | 変わること・残ること |
|---|---|
| 元案 | 確認した訪問先と条件から作る、比較の基準となる予定 |
| 時間をずらす案 | 訪問先を保ち、順番や時刻を変える。例：大須を先に回り、名古屋城を後にする |
| 場所をずらす案 | 必須の名古屋城を保ち、変更可能な訪問先を興味に合う別の候補へ交換する。例：大須商店街から万松寺へ |

提示するのは**元案と最大2つの代替案**です。条件によって代替案が成立しない場合は、その理由を表示します。必ず3案が揃うわけではありません。

### 3. 理由と不利益を見て、自分で選ぶ

各案の「理由・不利益・不確実性」から、変更した理由、得られる体験、失う体験や増える負担、不明な情報を確認できます。場所案で歴史体験が増える一方、食・買物の機会を入れ替えることや、避けたい時間帯との重なりが残ることも伝えます。

気に入った案を本人が「採用」すると、旅程を保存します。同じブラウザで再読込しても選んだ旅程を確認でき、条件を変えて再提案することもできます。**再提案しただけでは、採用中の旅程は変わりません。**



## Google技術の活用

| 技術 | 用途・選定理由 |
|---|---|
| Firebase Hosting | React / TypeScriptの画面を配信し、URLを開いて日英で利用できるようにする |
| Cloud Run | FastAPIとPython Plannerを実行し、入力検証・生成・採用のAPIを提供する |
| Firebase Authentication | 匿名認証のUIDで旅程の所有者を確認し、利用開始時の登録の負担を減らす |
| Cloud Firestore | 旅行条件・提案・採用状態を保存し、再読込後も選んだ旅程を確認できるようにする |
| Vertex AI / Gemini | 日英の希望を共通の条件へ構造化し、確定した事実から案の理由・不利益・不確実性を説明する。認証・権限・タイムアウトはサーバー側で管理する |
| Google Maps Routes API | 事前取得した12地点間・方向付き132通りの徒歩推定を利用し、訪問順や場所を変えたときの時間・距離を比較する |

GeminiにはGoogle Gen AI SDKからVertex AI経由で接続します。構成と責務の詳細は[アーキテクチャ](docs/ARCHITECTURE.md)、施設情報・経路の出典と扱いは[データの説明](docs/DATA.md)を参照してください。

## 現在の対応範囲と、今後確かめたいこと

現在は、事前に情報を確認した名古屋の候補から選ぶ、同一日内の徒歩計画に限定しています。候補外の施設の自由追加、複数日、公共交通、旅行中のGPS追従、予約・決済の実行は対象に含めません。

リアルタイムの混雑予測・待ち時間計測は行っていません。時刻や場所を変えただけで実際の混雑が減ったとは主張しません。「本人が知らなかった場所」と、客観的に知名度が低い・空いている場所も区別します。

今後は、案の違いや不利益を理解して選べるか、未選択だった施設へ興味を持てるかを利用テストで確かめます。そのうえで地域の施設・観光事業者と候補や受入条件の更新方法を整え、実際の訪問、待ち時間、満足度、地域への効果を検証していきます。

## ローカルで動かす

このリポジトリをcloneし、ルートディレクトリで実行してください。Gitと[Volta](https://docs.volta.sh/guide/getting-started)が必要です。プロジェクトではNode.js 24.22.2 / npm 11.19.1を固定しています。

### 画面を試す（架空の開発モック）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Profile frontend
npm run dev:frontend
```

[http://127.0.0.1:5173](http://127.0.0.1:5173)を開きます。この構成はAPIキー・Python・Javaが不要です。**初回セットアップの既定値は架空の施設・経路を使う開発モックで、公開アプリの名古屋実データとは異なります。** 既存の`.env`は上書きしません。

### 名古屋の実施設データとローカルAPIを使う

bootstrap用のPython 3.11以上も用意し、full環境をセットアップします。実行用のPython 3.13.5、Firebase CLI、emulator用のJava 21はセットアップで準備します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Profile full
```

セットアップ後、ローカル設定を次のように変更します。

| ファイル | 設定 |
|---|---|
| `backend/.env` | `DATA_MODE=curated` |
| `frontend/.env` | `VITE_USE_MOCKS=false`、`VITE_AREA_ID=nagoya-central`、`VITE_USE_FIREBASE_EMULATORS=true` |

3つのターミナルを使い、それぞれリポジトリのルートで、次の順に起動します。

```powershell
# ターミナル1：emulatorの起動完了を待つ
npm run emulators
```

```powershell
# ターミナル2
npm run dev:backend
```

```powershell
# ターミナル3
npm run dev:frontend
```

画面は[http://127.0.0.1:5173](http://127.0.0.1:5173)、APIの稼働確認は[http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)、API定義は[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)です。

この構成で実施設データ・HTTP API・認証・保存を確認できます。実Geminiを利用するにはVertex AIの権限・接続設定が、Web地図の表示にはGoogle Mapsの設定が別途必要です。未設定でもフォーム入力と定型説明・一覧表示で確認できます。詳細とMac/Linuxの手順は[開発手順](docs/DEVELOPMENT.md)を参照してください。

## 検証コマンド

```powershell
# full環境セットアップ後：backend・契約・frontendの基本検証
npm run verify:foundation

# Chromiumを準備
npm exec --prefix frontend -- playwright install chromium

# 名古屋実施設＋ローカルHTTP API・認証・保存の日英操作検証
npm run verify:curated-flow

# 地図の読み込み失敗時にも操作を続けられることを検証
npm run test:maps --prefix frontend
```

`verify:curated-flow`は検証用のemulator・API・画面を起動し、終了時に停止します。既存の開発サーバーとは別のポートを使用します。この検証と地図の故障検証に、実Gemini・外部の地図サービスの動作確認は含みません。検証範囲と使用ポートは[開発手順](docs/DEVELOPMENT.md#検証)を参照してください。
